# 日本ゲーム観測台 / Japan Game Observatory

日本游戏厂商新作发布的每日监测台。定期扫描日本游戏媒体，按
**公司 → 作品 → 新闻原文 → 参考 URL → 实机/预告视频 → 全球玩家舆论期待度**
六个维度编排成可视化页面。

## 打开方式

双击 `index.html` 即可（纯静态，无需服务器、无外部依赖、可离线查看）。

## 目录结构

```
jp-game-observatory/
├── index.html          页面骨架（Tab / KPI / 工具栏 / 抽屉）
├── assets/
│   ├── style.css       暗色观测台主题
│   └── app.js          渲染与交互（筛选、排序、搜索、详情抽屉）
└── data/
    └── data.js         ★ 唯一数据源 — 自动巡检任务只改这个文件
```

`data/data.js` 用 `window.OBSERVATORY = {...}` 挂载，经 `<script src>` 引入，
因此 `file://` 直接打开也能加载，不受浏览器跨域限制。

## 页面模块

页面按**手游优先**编排：手游是重点信息区，主机 / PC 为次要区。

| 模块 | 内容 |
|---|---|
| KPI 行 | 手游条目 · 事前登录中 · 已配信 · 手游厂商 ／ 主机・PC 条目 · 厂商覆盖 |
| 本期综述 | 观测窗口内的整体判断（7 条要点，手游视角优先） |
| **手游新作（重点区）** | 每张卡含 10 类维度（见下）。配信状况 / 对应 OS / 课金形态 / 开发配信体制 / 配信地域 / 事前登录 / 玩法特征 / 世界观 / CV 阵容 / IP 系谱。跨平台作品额外标注「跨平台」徽章并列出全平台 |
| **主机・PC（次要区）** | 紧凑卡片：公司 · 作品 · 平台 · 发售日 · 期待度，支持卡片/列表两种视图 |
| **厂商覆盖** | 指定 50 家厂商监测名单，按四分类展示覆盖状态，可展开关联作品 |
| 期待榜 | Famitsu 读者期待榜（含票数条形对比） |
| TGS2026 前瞻 | 会期、主题、各社展位与展出内容 |
| 详情抽屉 | 点卡片展开：手游条目会额外展示完整 Mobile Spec 区块、事前登录奖励、玩法与世界观 |

手游区支持按**配信状态**排序（事前登录中 → 配信日未定 → 已配信），
主机・PC 区支持按平台筛选与卡片／列表视图切换。

**跨平台作品两边都收**：`platformClass: "multi"`（手机 + 主机或手机 + PC）的作品，
既能在手机上玩、也是主机/PC 作品，因此**同时出现在手游区与主机・PC 区**，
手游区的卡片会打上「跨平台」徽章并额外列出全平台，避免只写 iOS/Android 造成误解。
（因此两侧条目数之和不等于总数，KPI 里有对应说明。）

交互：Tab 切换、全文搜索、平台筛选、三种排序（期待度 / 发表时间 / 公司）、
卡片与紧凑两种视图、ESC 关闭抽屉。

## 数据字段

```js
{
  id, company, companyJp, bucket,          // bucket: "new" | "update"
  platformClass,                           // "mobile" | "pc" | "console" | "multi"（全部条目显式标注）
  announceDate,                            // 发表或本次更新日
  title: { jp, cn, en },
  genre, platforms[], release, releasePrecision,
  summary,                                 // 内容摘要
  highlight,                               // 一句话要点
  news:   [{ source, url }],               // 新闻原文与参考来源
  videos: [{ label, platform, url }],      // 实机 / 预告 / 官方渠道
  hype:   { score, signals[] },            // 期待度 0-100 + 评估依据
  tags[], caution,                         // 可选

  /* 手游专属维度（platformClass: "mobile" 时必填，卡片与抽屉均据此渲染） */
  mobile: {
    status,        // 配信状况：事前登録受付中 / 配信予定 / 正式サービス中
    os[],          // 对应 OS
    monetization,  // 课金形态
    preReg: { open, since, reward },   // 事前登录（open=true 时卡片高亮展示）
    developer, publisher,
    region,        // 配信地域
    distribution,  // 配信方式（如「ブラウザ配信」）
    payment[],     // 支付手段
    ipSource, series,   // IP 出处 / 系列背景
    features[],    // 玩法特征
    synopsis,      // 世界观 / 故事
    cast           // 角色与配音
  }
}
```

`platformClass` 现在**全部条目均显式标注**（`mobile` 8 / `multi` 1 / `pc` 3 / `console` 25）。
若某条遗漏，`app.js` 的 `platformClassOf` 会从 `platforms` 兜底推断：
含 iOS / Android / 浏览器且不含主机平台 → `mobile`；两者都有 → `multi`。
新增条目请**显式写出**该字段，不要依赖推断。

另有 `meta`（更新时点、观测窗口、数据源清单、期待度口径说明）、
`companies`（厂商监测名单）、`mostWanted`（期待榜）、`tgs`（展会信息）、`digest`（本期综述）。

本站是**日本游戏厂商的观测台**，收录以下三类：

| 类型 | 说明 | 示例 |
|---|---|---|
| ① 日本厂商自研手游 | 基础盘 | 《雨のちハレ女》（GAME FREAK）、《誰ガ為のアルケミスト ポートマスターズ》（KMS） |
| ② **日本 IP 授权改编手游** | IP 持有方（多为日本方）主导。**不会出现在厂商名检索里，必须按 IP 名直接搜** | 《ONE PIECE 海のごちそうレストラン》（カイロソフト × バンダイナムコ）、《ハイキュー!! ALL Challengers》（東宝 TOHO Games 自营）、《BLEACH Mirrors High》（バンダイナムコ） |

### ⚠️ 明确排除：中国资本企业

**中国资本的企业**开发或发行的作品**一律不收**，包括但不限于：
腾讯（Level Infinite／TiMi Studio／Fizzglee Studio）、网易（NetEase／Naked Rain）、
米哈游、鹰角、FunPlus／趣加系（含杭州爪印工作室 Pawprint Studio）、bilibili 系发行、
Garena、心动、莉莉丝、叠纸等。

**即使 IP 是日本发源的也不例外** —— 判断标准看**开发・发行的资本归属**，不看 IP 出处。
例如「Capcom 授权 × 腾讯 TiMi 开发」的《怪物猎人 Outlanders》同样不收。

> 已按此规则移除的条目：《無限大 ANANTA》（网易）、《チェイシング・カレイドライダー》（腾讯）、
> 《モンスターハンターアウトランダーズ》（腾讯）、《アニモ Aniimo》（杭州爪印工作室 / FunPlus 系）。
> 巡检任务里有对应的全库关键词扫描校验（腾讯／网易／Tencent／NetEase／FunPlus／Pawprint 等），防止回流。

移动端独占作品最优先；跨平台作品（手机 + 主机 + PC）也收，见上文「跨平台作品两边都收」。

> 维护提示：②③ 是历史漏收的主要来源。每日巡检必须按 **IP 名逐个检索**，
> 并有一步「漏收核查」——挑 2-3 个近期热门动漫 IP 确认是否已有未收录的日方主导手游新作。

## 来源与链接策略（重要）

本台**只收录真实存在、可点开的来源**，不接受任何推测性链接。

**禁止两类别名链接：**

| 禁止 | 原因 |
|---|---|
| `youtube.com/results?search_query=...`、`x.com/search?q=...` 等**搜索结果页** | 不是具体内容页，链接会随检索结果漂移，对读者无意义 |
| **未经原文明确写出的**社媒账号（如 `@xxx_pr`）或频道 handle | 属于推测，极易指向不存在或错误的账号 |

**允许的来源类型**（不必强求 YouTube / X 两个平台）：

- 官方新闻稿 / 官方作品页 / 官方 X（原文中明确出现的账号）
- 日本游戏媒体：AppBank / GameBiz / QooApp / ファミ通 / 4Gamer / GameMeca / 電ファミ etc.
- 海外媒体：Anime News Network / Eurogamer / Polygon / Gurugamer / VICE etc.
- 商店页：Steam / App Store / Google Play（商店页自带预告影像，可作视频源）

**判定标准**：一条媒体把信息说清楚 + 一条来源能把影像放出来，即视为达标。
拿不到确切视频 ID 时，**退回到报道该作品的媒体文章页**（文中通常内嵌 PV），
而不是拼凑搜索页链接或猜测账号名。

> 环境限制：本机沙箱无法访问 `youtube.com` / `x.com` / `play.google.com` /
> `store.steampowered.com` 等域名，因此**无法自动做外链存活探测**。
> 链接真实性目前依赖"必须来自实际检索结果"这一条人工可核查的规则来保证。

每家条目含：

```js
{
  name,      // 日文全称
  short,     // 简称
  status,    // "covered" 已建作品卡 | "partial" 部分覆盖 | "watch" 待观察
```

**覆盖状态会随每日巡检自动推进**：当「待观察」厂商出现新作发表时，
巡检任务会为其建卡并把状态改为 `covered`，同时写入 `gameIds` 关联。

## 期待度口径

```
期待度 = 日本侧信号（Famitsu / 媒体期待榜票数与排位）× 40%
       + 全球媒体覆盖广度（多语种媒体报道量）× 30%
       + 社媒与预告片声量 × 30%
```

**这是公开信号的定性综合评估，不是平台真实流量数据**，仅供趋势横向比较。
每个条目的 `hype.signals` 都列出了该分数的具体依据，页面详情抽屉内可查。

## 自动更新

已挂每日巡检任务（09:00，自 2026-09-16 起）：自动搜索日本游戏媒体 → 识别新增作品与状态变更 →
写回 `data/data.js` → 校验结构 → 刷新页面数据。

巡检任务的硬约束：

- **只写 `data/data.js`**，不改 `index.html` / `assets/*`
- **绝不编造作品名、发售日、视频 ID、社媒账号**
- **不使用搜索页链接**，来源必须是实际检索命中的具体页面
- 每条至少 1 个 `news` 源、1 个 `videos` 源；手游条目必须带完整 `mobile` 子对象
- 写回后跑 `node --check data/data.js` 做语法自检
